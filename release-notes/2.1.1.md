RestoreSafe 2.1.1 fixes the log on network shares.

## Fixed

- **The log is written again when the backup directory is on a network share.** With 2.1.0, some network shares (for example a NAS) refused the log: backups, restores and verifications worked, but their log stayed empty, and **Show log** showed nothing. 2.1.1 writes the log as 2.0 did, on every drive that takes the backup files.

## Before you update from 2.1.0

Your backups are complete and unaffected; only their logs are empty. The lines of each empty log are still on your computer, in a file in your TEMP folder named `restoresafe-<number>-<date>_<ID>.log` (to open the folder, type `%TEMP%` in the address bar of File Explorer). To get a log back, copy that file over the empty log of the same name in your backup directory. RestoreSafe doesn't delete these files.

## Download

1. Download `RestoreSafe-2.1.1.zip` below.
2. Extract it to any folder. When you update, replace `RestoreSafe.exe` and keep your `config.yaml`.

RestoreSafe is not signed with a paid code-signing certificate, so on first start Windows may show "Windows protected your PC" (SmartScreen, "unknown publisher"). Click **More info**, then **Run anyway**. Windows asks only on the first start of a downloaded version.

On Windows 11 with **Smart App Control** turned on, Windows may block RestoreSafe without offering **Run anyway**. Smart App Control allows only programs that are signed or known to Microsoft. To run RestoreSafe, turn it off in Windows Security → App & browser control → Smart App Control settings. On older Windows 11 versions it can only be turned on again by reinstalling Windows.

Optional, for checking that the download is unchanged: download `SHA256SUMS.txt` into the same folder as the ZIP and run this in PowerShell there. It prints `True`:
```powershell
(Get-FileHash .\RestoreSafe-2.1.1.zip).Hash -eq (Get-Content .\SHA256SUMS.txt).Split(' ')[0]
```
